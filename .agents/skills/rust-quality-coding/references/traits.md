# Trait 与公共接口的取舍

trait 是一份能力协议：它让泛型代码能要求某些操作，也让不同实现能在一个明确边界上互换。它不是类层级，也不是所有模块都应先抽出的接口。

## 先判断是否需要抽象

从具体类型开始通常最便宜。出现以下任一需求时，trait 才有稳定的理由：调用方应能提供实现、核心逻辑需要测试替身、多个实现共享同一操作、或插件需要在运行时进入集合。

若变体有限且由当前 crate 控制，用 `enum` 往往更好：每种状态可携带不同数据，新增变体会迫使所有 `match` 重新审视。trait 则把扩展权交给实现者，调用方不能穷尽列举具体类型。

```rust
// 封闭：所有状态属于这个协议本身。
enum RetryPolicy { Never, Fixed(Duration), Exponential }

// 开放：调用方可以定义新的实现。
trait Clock {
    fn now(&self) -> Instant;
}
```

一个 trait 的方法应共同描述一项能力。把“如何创建”“如何持久化”“如何序列化”和“核心业务操作”组合成一个大 trait，通常意味着使用方被迫依赖不需要的方法。构造可放在具体类型、自由函数或另一个明确的工厂协议中。

## 泛型、`impl Trait` 与 `dyn Trait`

它们都能表示“满足某项能力”，但绑定时间不同：

| 形式 | 谁选择具体类型 | 适合什么场景 |
| --- | --- | --- |
| `fn f<T: Trait>(value: T)` | 调用方；每次调用可不同 | 需要静态分发，函数会持有或返回 `T` |
| `fn f(value: impl Trait)` | 同上，是简单泛型参数的写法 | 只需写清输入能力 |
| `fn f() -> impl Trait` | 实现方；所有返回路径是同一个隐藏类型 | 隐藏实现细节，不需要动态切换 |
| `&dyn Trait` | 运行时；调用方保有对象 | 临时借用的动态分发 |
| `Box<dyn Trait>` / `Arc<dyn Trait>` | 运行时；容器或结构体持有对象 | 异质集合、插件或延迟选择实现 |

返回 `impl Trait` 不是“返回任意实现”。一个函数仍然只能选择一种具体返回类型；如果分支需要产生不同实现，先问是否应使用 enum，只有确实需要开放扩展或异质存储时才用 trait object。

### 对象安全是接口设计反馈

准备以 `dyn Trait` 使用的 trait，方法应能通过一个未知大小的对象调用。实例方法通常以 `&self` 或 `&mut self` 为 receiver；构造函数、返回 `Self` 的方法或泛型方法不应混进这个动态接口。若它们仍有价值，可写成具体类型的关联函数，或在 trait 中加 `where Self: Sized`，使其不属于 trait object 的可调用表面。

原生 `async fn` in trait 对静态分发很方便，但它不直接给你一个可对象化的 trait。需要 `dyn` 异步接口时，明确选择盒装 future 的签名或项目已采用的宏/库方案，并接受相应的分配、`Send` 和生命周期语义；不要在两种模型之间含混切换。

## 关联类型和 trait 类型参数

关联类型表示“某个实现确定一种关联结果”：

```rust
trait Decode {
    type Output;
    fn decode(&self, input: &[u8]) -> Result<Self::Output, DecodeError>;
}
```

同一个类型通常只应有一种 `Output`。若某类型要分别处理多种右侧操作数，类型参数更合适，例如 `Add<Rhs>` 可以针对不同的 `Rhs` 提供实现。选择的关键不是少写尖括号，而是实现者是否必须固定结果类型。

复杂 bound 用 `where` 排版，让约束紧挨着它约束的关联类型；不要为了短签名把不相关的类型参数传过整条调用链。

## 标准 trait 表达已有语义

只实现行为符合类型含义的标准 trait：

| 需要的能力 | 选择 | 注意点 |
| --- | --- | --- |
| 开发者可诊断表示 | `Debug` | 大多数公共数据类型可 `derive(Debug)` |
| 面向用户的稳定文本 | `Display` | 手写格式；实现后自动获得 `ToString`，不要单独实现它 |
| 合理的空/初始值 | `Default` | 不要把“凑出的零值”伪装成业务默认值 |
| 相等或哈希 key | `PartialEq`，必要时 `Eq`/`Hash` | 浮点 NaN 不满足 `Eq`；语义相等应稳定 |
| 总排序或 BTree key | `Ord` 与相应比较 trait | 排序顺序应是领域认可的总序 |
| 明确复制 | `Clone` | 复制成本和语义应在调用处可见 |
| 隐式廉价复制 | `Copy` + `Clone` | 仅用于复制自然、所有字段也 `Copy` 的小值 |
| 无损拥有转换 | `From<T>` | 实现 `From` 即可得到 `Into` |
| 可能失败的转换 | `TryFrom<T>` | 不要把截断或校验失败藏在 `as` 中 |
| 解析文本 | `FromStr` | 让 `parse()` 成为一致入口 |
| 显式借用视图 | `AsRef`/`AsMut` | 可用于泛化入口；避免无意义的泛型传播 |
| 智能指针式透明访问 | `Deref`/`DerefMut` | 不要用作继承或给包装类型偷偷扩大 API |

派生不是默认任务。它会把类型承诺给调用者：例如 `Clone` 允许复制，`Ord` 宣称排序有业务意义，`Default` 宣称无参数构造合理。按实际使用 derive，并让字段的行为与整体语义一致。

## coherence、方法冲突与模块边界

孤儿规则要求 `impl Trait for Type` 中的 trait 或类型至少一个属于当前 crate。不能实现外部 trait 到外部类型时，newtype 是有意的适配边界，而不是绕规则的技巧。

为某 trait 写 blanket implementation 前，先看它是否会占掉未来更具体的实现空间。方法同名时，Rust 不存在“子类覆盖”；使用 UFCS（`<Type as Trait>::method(...)`）说明调用哪个协议。只有调用方必须看见的协议才 `pub`，其余实现细节留在模块内。
